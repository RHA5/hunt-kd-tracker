# Hunt: Showdown — KD Tracker & Progress Calculator

Стильный, интерактивный веб-дашборд (Single Page Application) для стримера по игре *Hunt: Showdown*, разработанный как альтернатива классическим гугл-таблицам. 

## 1. ФИЛОСОФИЯ И СУТЬ ЧЕЛЛЕНДЖА
*   **Главная цель:** Поднять общий КД (Kill/Death) аккаунта до **2.0**.
*   **Контекст задачи:** Аккаунту более 5 лет. Накоплен огромный исторический «багаж» смертей (более 32 700). На старте челленджа общий КД составлял **1.72** (дефицит для достижения цели — около 9 000 чистых убийств без смертей). 
*   **Игровая атмосфера:** Проект выполнен в мрачной готическо-оккультной стилистике игры Hunt: Showdown (штат Луизиана, конец XIX века). Оформление использует темную палитру, золото, латунь, элементы старой бумаги, виньетки и викторианские шрифты.
*   **Интерактивность:** Дашборд не просто сухой калькулятор — он общается со стримером и зрителями. В конце каждой сессии генерируется всплывающее HTML-окно с персонажами, которые иронично подкалывают стримера за плохую игру или хвалят за успех на основе КД дня:
    *   *КД дня < 2.0 (Провал):* Всплывает Отец Бездны Манус (из Dark Souls) с предложением удалить Хант и регать Дарк Соулс.
    *   *КД дня 2.0 - 4.0 (Норма):* Всплывает разработчик игры Дэвид Файфилд с ироничными комментариями о качестве серверов и регистрации попаданий.
    *   *КД дня > 4.0 (Триумф):* Всплывает Билли Херрингтон со знаменитыми цитатами.

## 2. МАТЕМАТИЧЕСКОЕ ЯДРО (ФОРМУЛЫ)

Главная особенность проекта — **честный, динамический прогноз**. Все расчеты времени и матчей базируются на реальной текущей игровой форме стримера (его KPG и DPG за время челленджа), а не на идеальных теоретических допущениях.

### Ключевые показатели:
- **Общий КД (L3):** `Всего_Убийств / Всего_Смертей` (отображается с точностью до 2 знаков, но в расчетах используются точные дробные значения).
- **Финальная цель 2.0 KD (Чистый дефицит киллов):** `(Всего_Смертей * 2.0) - Всего_Убийств`.
- **Оптимистичный прогноз:** (Сценарий достижения цели, если стример всегда будет играть на уровне своего рекорда KD). Формула: `=IF(КД_Челленджа <= 2.0; "∞"; Дефицит_Киллов / (KPG_Челленджа - (2.0 * DPG_Челленджа)))`.
  *Если текущая эффективность в челлендже ниже или равна 2.0, цель математически недостижима, поэтому выводится символ бесконечности `∞`.*
- **Промежуточная цель (Ближайшая цель по KD):** Высчитывает следующий микро-шаг по КД. Рассчитывается как: `=ROUND(Общий_КД; 2) + 0.01`. Это убирает визуальный баг округления и мотивирует стримера двигаться по сотым долям КД. Также показывает сколько убийств, матчей и стримов осталось до этой микро-цели, и примерную дату достижения.
- **Осталось убийств до цели:** `ROUNDUP((Всего_Смертей * Ближайшая_Цель) - Всего_Убийств)`.
- **Стрик дней в которых KD>2:** Подсчет количества стримов подряд, в которых эффективность была выше целевой отметки.

## 3. СТЕК ТЕХНОЛОГИЙ И АРХИТЕКТУРА
*   **Фронтенд:** HTML5, Tailwind CSS (CDN), Chart.js (CDN) для построения динамического графика эффективности по ходу стрима.
*   **Хостинг:** Бесплатный статический хостинг GitHub Pages.
*   **Бэкенд / База данных:** Supabase (PostgreSQL), доступная через защищенные RLS-политики.
*   **Многостраничная архитектура (MPA):** Каждый экран является независимым HTML-файлом. Это разгружает контекст ИИ и упрощает отладку кода.

### Карта файлов проекта:
1.  `index.html` — **Главный экран зрителя**. Отображает чистую статистику, таймер и прогресс-бар. Кнопки управления скрыты. Доступен всем по прямой ссылке. Содержит встроенный механизм автообновления (polling) каждые 5 секунд для идеальной работы в качестве источника браузера в OBS.
2.  `obs.html` — **Компактный виджет для OBS**. Облегченная версия без фона, с фокусом на статистику дня и прирост КД. Предназначена для встраивания поверх игры.
3.  `admin.html` — **Панель управления стримера**. Содержит кнопки старта охоты, степперы ввода и кнопку записи матча.
4.  `login.html` — **Экран авторизации**. Атмосферный заслон ввода логина/пароля. Защищает `admin.html` от несанкционированного доступа.
5.  `history.html` — **Лог сыгранных сессий**. Удобная таблица с архивом всех стримов из базы данных Supabase.
6.  `charts.html` — **Аналитика и графики**. Показывает глобальные графики роста КД аккаунта за всё время.
7.  `TYPOGRAPHY.md` — Дизайн-система (паспорт шрифтов, размеров и отступов).
8.  `.clinerules` — Свод законов и правил взаимодействия с ИИ-агентом.

## 4. БЕЗОПАСНОСТЬ (RLS & AUTH GUARD)
Поскольку GitHub Pages является публичным хостингом, защита админ-панели реализована на двух уровнях:
1.  **Auth Guard (JS-роутер):** При загрузке `admin.html` скрипт проверяет наличие сессии авторизации в `localStorage`. Если пользователь не вошел в систему, страница мгновенно перенаправляет его на `login.html`.
2.  **Row Level Security (RLS в Supabase):** База данных настроена так, что запросы на чтение данных (`SELECT`) разрешены любым анонимным пользователям (чтобы у зрителей на `index.html` крутилась статистика). Запросы на запись, изменение или удаление (`INSERT`, `UPDATE`, `DELETE`) заблокированы на уровне сервера базы данных для всех, кроме авторизованного администратора.

## 5. СТРУКТУРА БАЗЫ ДАННЫХ (SUPABASE)

### 1. hunter_profile (Итоги и константы)
*   `total_kills` (INT) — Всего убийств на аккаунте.
*   `total_deaths` (INT) — Всего смертей на аккаунте.
*   `total_matches` (INT) — Сыграно матчей за все время.
*   `start_kills` (INT) — Убийства на момент начала челленджа (19.05.2026).
*   `start_deaths` (INT) — Смерти на момент начала челленджа (19.05.2026).
*   `start_date` (TIMESTAMPTZ) — Дата старта челленджа.
*   `mmr` (INT) — Текущий рейтинг.
*   `target_kd` (NUMERIC) — Глобальная цель (2.00).

### 2. sessions (Стрим-сессии)
*   `start_time` (TIMESTAMPTZ) — Начало сессии.
*   `end_time` (TIMESTAMPTZ) — Конец сессии.
*   `kills` / `deaths` / `matches_count` — Статистика за конкретный стрим.
*   `is_active` (BOOLEAN) — Флаг текущей сессии.
*   `condition_rating` (INT) — Самочувствие стримера (1-10).
*   `comment` (TEXT) — Заметки стримера о сессии.
*   `loadout` (TEXT) — Используемое оружие в рамках этой сессии.

### 3. matches (Лог матчей)
*   `session_id` (UUID) — Связь с таблицей `sessions`.
*   `kills` / `deaths` — Результат конкретной катки.

### 4. auth_config (Доступ)
*   `login` / `password` — Данные для входа в админ-панель.
